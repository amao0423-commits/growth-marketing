## 3. URL構成

| URL | 内容 | 扱い |
|---|---|---|
| `/` | トップ | 新規 |
| `/category/{slug}/` | カテゴリ一覧（8種） | 新規・静的URLを持たせる |
| `/category/{slug}/page/{n}/` | ページ送り | 新規 |
| `/news/{id}/` | ユーザー投稿記事 | 新規 |
| `/blog/{slug}.html` | 既存37記事 | **URL据え置き**・著者を編集部に変更 |
| `/submit/` | 入稿フォーム | 新規 |
| `/mypage/` | マイページ | 新規・要ログイン |
| `/ad/` | 広告枠掲載のご案内 | 新規 |
| `/index.html`（旧LP）, `/contact.html` | 旧サービス紹介 | **削除** → `/` へ301 |

既存記事のURLを変えないのは、被リンクとインデックスを失わないため。
`.html` 拡張子はSEO上の不利にならない。

ベースは白とグレー。パステルは**カテゴリ識別子**として機能的に使う。

| カテゴリ | 背景 | 文字 |
|---|---|---|
| K-POP | `#FFD9E4` | `#8A3A55` |
| 韓国情報 | `#FFE2CC` | `#94502A` |
| エンタメ | `#E7DCFF` | `#5B429B` |
| IT・テック | `#D6E7FF` | `#2B5A93` |
| SNS・マーケ | `#D3F0E4` | `#1F6B52` |
| ライフ | `#FFF0C4` | `#846412` |
| 旅行 | `#CDECF2` | `#1F6A76` |
| ビジネス | `#E3E5EA` | `#474E5C` |
| 編集部（アイキャッチ専用） | `#E4EDD6` | `#54682F` |

**PR表記だけはパステルにしない。** 黒地に白抜き。景品表示法のステルスマーケティング

- 見出し・マストヘッド：Zen Old Mincho
- 本文・UI：Noto Sans JP

### アイキャッチ自動生成
画像未登録の記事は、カテゴリのパステル＋ドットパターン＋タイトル＋ADPRESSラベルで
SVGを生成する。編集部記事はセージグリーンに「アドプレス」ロゴのみで統一。
サーバー側で生成しPNG化してOGP画像にも使う。

## 5. 投稿フロー

```
ログイン（Google / LINE / X / Apple）
  → 入稿フォーム
  → AI自動審査
      ├ auto_approve      → 15分ディレイ後に公開
      ├ revision_required → マイページに差し戻し
      ├ human_review      → 編集部キュー
      └ reject            → 掲載不可を通知
  → 公開・マイページのお知らせに通知
  → 14日以内に紹介リンクを提出
  → 掲載1ヶ月後にPVレポート公開
```

### リンク本数

| | 上限 | rel属性 |
|---|---|---|
| 無料投稿 | 本文中＋参考リンク**合計2本** | `nofollow` |
| 広告記事 | 合計**5本** | `sponsored` |

エディタ側で3本目の挿入をブロックし、広告枠の案内を表示する。

### 公開後の編集
本文とアイキャッチは**公開から1ヶ月間のみ**編集できる。URLは変わらない。
編集後はあらためてAI審査を通す（審査中も記事は公開されたまま）。

### 紹介リンク
掲載記事を自社サイトのお知らせ欄やSNSで紹介し、そのURLをマイページから提出する。
14日以内に提出がない場合は記事を取り下げる。

告知依頼の文面テンプレート：

```
■メディア掲載実績

「該当タイトル名」が、プレスリリースサイト「アドプレス」に掲載されました。

アドプレス掲載ページ：記事リンク
```

## 6. 広告枠（¥20,000／1本・税別）

- 記事の作成代行（1,500字程度・任意）
- リンクを5本まで挿入可（通常は2本まで）
- トップページのPR枠に7日間固定表示
- カテゴリ上部に14日間表示
- 画像5点まで／記事は恒久掲載
- 掲載1ヶ月後にPVレポートを公開
- 紹介リンクの提出は不要

**オンライン決済は行わない。** 掲載後に請求書を発行し銀行振込で回収する。
管理ステータスは `inquiry → awaiting_draft → producing → published → invoiced → paid`。

## 7. 既存37記事の移行

```bash
python3 scripts/convert_legacy.py --src ./blog --out ./blog_converted --report report.csv
```

処理内容：

1. `<title>` の `｜Growth Marketing ブログ` → `｜アドプレス`
2. 著者表記 → `アドプレス編集部`、著者ボックスを新しい編集方針文に差し替え
3. ヘッダー・フッターをアドプレスのナビに置換
4. パンくずを `ホーム / カテゴリ名` に
5. 記事末尾の「無料相談」CTA → 投稿CTAに差し替え
6. 本文中の営業文を**文単位で削除**（ブランド名だけ置換すると、実体のない編集部が
   サービスを提供している文になってしまうため）
7. JSON-LD（Article）を付与。`publisher` はアドプレス
8. 旧LPへの内部リンクを除去、CSSパスを `/assets/adpress.css` に変更

`--report` でCSVが出力される。どのファイルの何が消えたか全件レビューできる。

### 変換後に手作業が必要な箇所

- **比較記事4本**（Instagram・TikTok・SNS・マーケ代行の10社比較）。第三者を実名で
  評価しているため、各社公式サイトへの出典リンク追加が必要。スクリプトでは判断できない
- **カテゴリの再割り当て**。現在は SNS運用/広告運用/SEO/コンテンツ → `sns`、
  ブランディング/比較 → `biz` にまとめている。`CATEGORY_MAP` で変更可能

## 8. AI自動審査

`docs/ai-review-prompt.md` に全文。要点のみ：

- 判定は `auto_approve` / `revision_required` / `human_review` / `reject` の4値
- **品質では落とさない。** 文章が拙いだけでは差し戻さない
- 確認項目：禁止コンテンツ／薬機法／景品表示法／ステマ規制／著作権／個人情報／
  リンク本数／スパム性／プレスリリースの体裁
- 投稿本文は必ず `<article>` タグで囲んで渡す。本文中の指示文をプロンプトとして
  解釈させないための境界
- `confidence` が 0.7 未満なら判定に関わらず人手に回す
- 目標：見逃し1%未満、誤検知10%未満、human_review送り15%以下

誤検知は投稿者の離脱に直結する。初期は human_review を厚めに取り、実データを見ながら
閾値を下げる。

## 9. データベース

`db/schema.sql` を上から順に流す（Supabase想定）。

主要テーブル：

| テーブル | 役割 |
|---|---|
| `profiles` | 投稿者。表示名・担当者名・連絡先 |
| `categories` | カテゴリとパステル配色 |
| `articles` | 記事本体。ステータス・種別・期限を保持 |
| `article_links` | 記事内リンク。本数制限をCHECK制約で担保 |
| `review_logs` | AI審査の全記録。プロンプト版も保存 |
| `referrals` | 紹介リンクの提出・確認・期限 |
| `ad_orders` | 広告枠の申込と請求管理 |
| `article_stats` | 日次PV。レポート公開日以降のみ本人が閲覧可 |
| `content_reports` | 掲載内容への通報 |

トリガーで自動化している処理：

- 公開時に `edit_deadline`（+1ヶ月）と `report_ready_at`（+1ヶ月）を設定
- 公開時に `referrals` を作成（広告記事・編集部記事は `waived`）
- `article_links` の増減に合わせて `articles.link_count` を同期

定期ジョブ（pg_cron想定）：

- `job_publish_scheduled()` — ディレイ公開（毎分）
- `job_referral_reminders()` — 期限3日前のリマインド（毎日）
- `job_remove_unreferred()` — 期限切れの取り下げ（毎日）

RLSは有効化済み。投稿者は自分の記事のみ、公開後1ヶ月以内のみ更新できる。
広告申込フォームと審査結果の書き込みは service role で行う。

## 10. 法務まわりの注意点

### ステルスマーケティング規制（景品表示法）
対価を受け取って掲載する記事には「PR」表記が**法的に必須**。

- 記事タイトル横にPRバッジ（黒地・白抜き）
- 一覧・カード表示でも同じバッジ
- 記事冒頭に「この記事は◯◯社から掲載費用を受け取って制作・掲載した広告記事です」
- 外部リンクは `rel="sponsored"`

### 紹介リンクの要求
掲載の見返りにリンクを要求する形は、Googleのスパムポリシーでリンクスキームに
該当する可能性がある。以下の建て付けにしている。

- dofollowを要求しない
- 規約上は「リンクの提供義務」ではなく「掲載記事の告知にご協力ください」
- 取り下げ理由は「掲載継続の意思確認が取れないため」と整理

### 投稿型メディアとしての免責
記事末尾に、内容の責任が投稿者にあること、編集部が正確性を保証しないこと、
通報窓口があることを明記する。`pages/article.html` に実装済み。

### 旧LPの削除
実在しないブランド「Growth Marketing」のサービス紹介・実績ページは削除する。
残すとE-E-A-T上のリスクになる。

## 11. 通知の設計

メールでの個別連絡は行わず、**マイページ内のお知らせページ**（`pages/notifications.html`）で
すべての連絡を届ける。届く通知は4種類。

| 種類 | 内容 |
|---|---|
| 公開 | 記事URL、告知のお願い、紹介文テンプレート、3つの期限、広告枠の案内 |
| 要対応 | 紹介リンクの提出期限が近い旨（期限3日前） |
| レポート | 掲載1ヶ月後のPVレポート公開 |
| 差し戻し | AI審査で修正が必要になった箇所と理由 |

登録メールアドレスへは「お知らせが届いています」という短い案内のみ送る（プロフィールから停止可）。
これは投稿者がお知らせに気づかず記事を取り下げられる事態を防ぐための最小限の通知。

## 12. 比較記事の修正

`scripts/fix_comparison.py` を `convert_legacy.py` の後に実行する。

```bash
python3 scripts/convert_legacy.py --src ./blog --out ./blog_converted
python3 scripts/fix_comparison.py --dir ./blog_converted --sources scripts/sources.csv
```

処理内容：

1. **架空企業のランキング項目を削除** — `tiktok-agency-comparison.html` の①が
   実在しない「Growth Marketing」だったため、項目・比較表の行・紹介文を削除し、
   ②〜⑩を①〜⑨に繰り上げ、「10選」「10社」を「9選」「9社」に修正
2. **関係性の明示を挿入** — 残り3本の①はCOCOマーケ（株式会社ホットセラー）。
   運営会社が提供するサービスであることを冒頭に明示（ステルスマーケティング規制）
3. **確認できない監修者クレジットを削除**
4. **出典リンクを記事末尾にアウトラインで追加** — `sources.csv` の `url` 列を
   記入した行のみ出力される

### sources.csv

41社分の行が用意されている。`url` と `checked`（参照日）を記入して再実行すると
出典セクションが生成される。URL未記入の行はスキップされる。

現時点で記入済みなのはCOCOマーケのみ。**他社のURLは未確認のため空欄**。
実在企業へのリンクは誤りがあると相手方に迷惑がかかるため、必ず公式サイトを開いて
確認したうえで記入すること。
